# Expected Q&A
**Why did you choose this track?** It demonstrates a complete assistant service with tools, memory, approvals, security, evaluations and an API.

**What makes it agentic?** It can select and invoke tools based on user intent and maintain bounded conversational state. The current prototype uses deterministic routing; a model-driven planner is an extension.

**Why MCP?** It standardizes tool exposure and lets compatible clients discover and call policy tools.

**How do you prevent prompt injection?** Retrieved content is treated as untrusted data, tools are allowlisted, and write actions are gated. A production system needs layered controls and tests.

**What does approval protect?** It prevents the agent from saving a draft without an explicit human decision.

**How do you evaluate it?** Fifteen task cases across two configurations, scored by tool choice and required evidence substring. Results are generated by running the eval script.

**What are limitations?** Synthetic policies/statuses, deterministic router, local memory, no real municipality integration, and no provider-cost accounting in demo mode.
